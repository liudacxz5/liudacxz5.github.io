🚀 从零构建本地数据湖仓：Apache Iceberg + MinIO + Trino 全攻略

摘要：本文记录了如何在 Windows (WSL2) 环境下，使用 Docker 打造一套基于 Apache Iceberg 的现代数据湖仓。涵盖了从 MinIO 对象存储搭建、Python (PyIceberg) 模拟业务数据写入，到 Trino 进行 SQL 数据分析的全流程。重点总结了在 Docker 网络配置、S3 协议兼容性以及数据类型校验上遇到的“深坑”与解决方案。

1. 架构设计：存算分离

为了体验最先进的 Data Lakehouse 架构，我们采用了典型的存算分离设计：

  • 存储层 (Storage): MinIO (模拟 AWS S3)，负责存放实际的数据文件 (Parquet) 和元数据。
  • 元数据管理 (Catalog): Iceberg REST Catalog，负责管理表的结构、快照和文件列表。
  • 写入计算 (Write): **Python (PyIceberg)**，模拟业务系统解析 Excel 并通过流式/批处理写入数据。
  • 查询计算 (Read): Trino，负责提供高性能的 SQL 查询服务。

5. 💀 踩坑实录 (血泪总结)

在搭建过程中，我遇到了几个“Boss 级”的报错，以下是通关秘籍：

坑位 1：Java SDK 的 UnknownHostException

  • 现象：Python 写入时报错 UnknownHostException: warehouse.minio。
  • 原因：AWS SDK (Java版) 在 REST Catalog 服务端运行，即使配置了 path-style，有时仍会强制使用虚拟主机模式 (warehouse.minio:9000)。Docker DNS 不认识这个域名。
  • 解决：
    1. 在 docker-compose.yml 的 minio 服务下添加 networks -> aliases，别名为 warehouse.minio。
    2. 添加环境变量 MINIO_DOMAIN=minio。

坑位 2：Docker 内外端口混淆

  • 现象：Trino 报错 Connection refused，或者 DataGrip 连不上。
  • 原因：混淆了 Docker 内部端口（8181, 9000）和 外部映射端口（18181, 19000）。
  • 原则：
    • 容器连容器 (Trino -> MinIO)：用 服务名 + 内部端口 (http://minio:9000)。
    • 宿主机连容器 (Python -> MinIO)：用 127.0.0.1 + 映射端口 (建议映射为 9000 以减少麻烦)。

坑位 3：WSL 的网络隔离

  • 现象：Python 脚本在 WSL 中运行，报错连不上 minio。
  • 原因：WSL 有独立的 /etc/hosts，不共享 Windows 的 hosts。
  • 解决：
    1. 在 WSL 中 sudo nano /etc/hosts。
    2. 添加 127.0.0.1 minio warehouse.minio。

坑位 4：数据写入的类型校验

  • 现象：报错 Mismatch in fields 或 unsupported type timestamp[ns]。
  • 原因：Iceberg 是强类型且严格校验 Schema 的。
    1. Pandas 的 int64 vs Iceberg int -> 需要强转 astype("int32")。
    2. Pandas 的 ns 时间戳 vs Iceberg us -> 需要强转 datetime64[us]。
    3. Iceberg required 字段 vs Pandas optional -> 需要用 pyarrow.schema(..., nullable=False) 手动定义。

坑位 5：Trino 配置洁癖

  • 现象：Trino 启动报错 Configuration property 'fs.native-s3.xxx' was not used。
  • 原因：REST Catalog 默认会下发凭证，导致 Trino 忽略本地配置。
  • 解决：设置 iceberg.rest-catalog.vended-credentials-enabled=false。
